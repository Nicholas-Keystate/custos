# PR #92: spec: seed the locator's carriage — HELD on the clean-root decision
Filed by dhh1128 at 2026-08-26T23:29:45Z

**This PR is held and should not be merged yet.** It is opened so the design is visible and reviewable, not to ask for a decision.

It carries the part of finding #85's repair that locator *assignment* depends on: the bracketed token at the start of a block, and dropping markdown bullets from normative text so the locator carries the enumeration the way `(a)`/`(b)`/`(c)` does in a statute.

It waits on the clean-root decision that #77 lists last "because it frames the rest." A locator is never reused within a lineage, so its permanence is both the value and the cost, and it is only worth paying once the thing being named holds still. Assigning permanent names to strata the connectome pass may excise spends permanence on text that will not survive, and restructuring afterwards threads insertion suffixes through a document whose purpose is legibility.

Written down now because the shape is cheaper to settle while the argument is fresh.

One unresolved defect is recorded in the seed rather than hidden: nothing stops a block's prose from beginning with something shaped like `[8.3.5.2]`, at which point a parser reads authored text as structure. CQT names the same failure at its step 3 and answers it by building its placeholder from characters that cannot appear in the input. Whether that answer is available here is not settled.

`<dfn>` is withdrawn from this and from #88, pending a term test.

Depends on #88. Relates to #85, #90, and #77.
